# Brace Map

把代码块里的缩进列表渲染成教材式的括号图（Brace Map），横向树、大括号连接，可导出 SVG / PNG。

Obsidian 插件，纯 JavaScript，无构建链、无 npm 依赖。

---

## 快速开始

在笔记里写一个 ` ```brace ` 代码块：

````
```brace
- 系统
  - 硬件
    - 传感器
    - 执行器
  - 软件
    - 固件
```
````

渲染出来就是：

```
                    ┌─ 传感器
          ┌─ 硬件 ─┤
          │         └─ 执行器
系统 ─────┤
          │         ┌─ 固件
          └─ 软件 ──┘
```

指令写在列表之前，一行一条，`键: 值` 的形式，可以混在列表中间写（解析器按行依次扫描，遇到列表项就进列表，遇到 `键: 值` 就当指令）。

## 指令

### `dir` — 展开方向

| 值 | 含义 |
|---|---|
| `lr` | 从左往右（默认） |
| `rl` | 从右往左 |
| `tb` | 从上往下 |
| `bt` | 从下往上 |

### `brace` — 括号形状

| 值 | 含义 |
|---|---|
| `curly` | 花括号 `{`（默认） |
| `square` | 方括号 `[` |

### `box` — 给指定层级画方框

值可以是单个数字、逗号分隔（`1,3`）、范围之外的组合，按**深度**生效（根节点深度为 1）。

```
box: 2
```

表示第 2 层的所有节点都带方框。清除写 `box: none`。

### 行尾 `{box}` — 只给单个节点画框

上面那个是按层，想精确点名某几个节点时，在行尾加 `{box}`：

```
- 系统
  - 硬件 {box}
  - 软件
```

只给「硬件」画框，不看层级。可以同时用 `box: N` 和行尾标记，两者取并集。

### `closing` — 末端闭合线

`closing: true` 时，叶子节点的连接线末端会画一小段竖线收口，像教材里的收尾。

### `title` — 标题

图上方居中显示的标题。也兼容把 `# 标题` 写在第 1 行。

### `maxwidth` — 节点文字折行宽度

单位是最终 SVG 坐标里的像素，**不随字号缩放**。超过这个宽度的节点文字会自动折行。

```
maxwidth: 240
```

不写或写错值就是完全不折行。

### `float` — 图文混排

| 值 | 含义 |
|---|---|
| `l` / `left` | 靠左浮动，文字在右侧绕 |
| `r` / `right` | 靠右浮动，文字在左侧绕 |
| `c` / `center` | 居中，不浮动 |
| `inl` / `inline` | 行内模式 |

**注意**：`left` / `right` 的**跨行环绕只在阅读视图生效**，编辑模式下默认关闭。原因见下面「图文混排」一节。

### `width` — 浮动时的宽度

```
width: 300
```

不写就按图自身宽度。也支持 `300px`、`50%` 这类 CSS 宽度值。

### `bg` — PNG 导出底色

| 值 | 含义 |
|---|---|
| 不写 | 透明（默认） |
| `theme` | 取当前主题的背景色 |
| 任意颜色值 | 如 `#1a1a1a`、`rgb(20,20,20)` |

## 行内样式

节点的文字里可以用 Markdown 行内语法：

| 写法 | 效果 |
|---|---|
| `**粗体**` | 粗体 |
| `*斜体*` | 斜体 |
| `~~删除线~~` | 删除线 |
| `==高亮==` | 背景高亮 |
| `[[某篇笔记]]` | 双链，点击跳转 |
| `[文字](https://...)` | 外链，点击用系统浏览器打开 |

双链和外链在导出的 SVG 里会保留为 `<a>`，图片里则变成普通文字。

### 公式

支持 `$...$` 行内公式和 `$$...$$` 块级公式。公式被当作**不可拆的原子**参与排版，不会被 `maxwidth` 从中间折断。

渲染走插件内自带的 MathJax（`vendor/tex-svg.js`，2MB 左右），输出**矢量** SVG，导出时不会糊。

为什么不用 Obsidian 内置的：Obsidian 安装包里的 MathJax 只带 CHTML 输出，出不了矢量。这是实测结论（`tex2svg` 出现 0 次，`CHTML` 出现 307 次）。

## 图文混排

这部分是本插件踩坑最多的地方，写清楚留给以后。

### 阅读视图

散文区（`.markdown-preview-sizer`）是**纵向 flex 容器**，代码块是它的直接子项。CSS 规范明确：**flex 容器的直接子项，`float` 不产生浮动效果**（计算值还是 `right`，布局上被忽略）。

所以阅读视图的浮动是 **JS 模拟**的：

1. 容器 `position: absolute`，贴住正文列的左/右边界
2. 遍历它后面的兄弟块，按真实渲染高度累积，算到图的范围为止
3. 给这些块加 `margin-right` + `max-width`（两个都要，只加 margin 时定宽的块不会变窄）
4. 重算前先复位上一次的改动，不叠加

这条路是稳的，静态渲染没有虚拟滚动，不用担心坐标系。

### 编辑模式

编辑模式是 CodeMirror 6，情况完全不同，值得单独记。

**第一个坑：`.cm-content` 是 flex 子项，但它是 BFC。**

`.cm-embed-block` 直接挂在 `.cm-content` 下（Obsidian 1.13.7 实测，中间没有 `.cm-line`，老版本可能有）。因为 `.cm-content` 是 flex 容器的子项，**flex item 天然建立独立格式化上下文**，所以 `float` 在这里**有效**，文字会真的绕上来。

**第二个坑：`contain: paint !important` 会把图整张裁掉。**

Obsidian 的 `app.css` 里有这么一条（从 `obsidian.asar` 里确认过）：

```css
.markdown-source-view.mod-cm6 .cm-content > [contenteditable=false] {
  contain: paint !important;
}
```

代码块 widget 正是 `.cm-content` 下 `contenteditable=false` 的子元素。`contain: paint` 把后代裁到自己的 padding box，**`overflow: visible` 对它无效**——两套机制不是一回事。表现为：SVG 在 DOM 里、`getBoundingClientRect` 报正常尺寸，但视觉上完全看不见。

修法：施加浮动时逐层检查祖先的 `contain` / `overflow` / `clip-path` / `opacity` / `visibility`，逐层写行内 `!important` 放开，到 `.cm-content` 为止。**`.cm-scroller` 及以上绝对不动**，改了会废掉滚动条。

**第三个坑：CM6 的高度账本。**

这是最要命的一个，也是为什么编辑模式的浮动默认关着。

CM6 用**累加行高**来估算文档总高和每行的位置。你点鼠标时，它拿纵坐标去翻这本账，算出「大概第几行」。

而 **block widget 会被单独记一条高度**。如果这个 widget 浮动起来（脱离流，实际占 0），账上还是原来的高度，两者就对不上：

```
CM6 账上文档总高   7504.13
DOM 实际高度       7334.34
差                 169.79   ← 正好是 widget 高度
```

差多少，光标就偏多少。实测点第 18 行，光标落到第 14 行，还能飘到行间空隙里。

**试过但没用的做法**：

- `cm.requestMeasure()` 主动重测：无效，`changed: false`，重测前后高度差恒为 0。因为 CM6 量的是 widget 自己的 rect，浮动不改变它，只是不再贡献给父容器。
- `height: 0` + `shape-outside`：无效。布局引擎的浮动排除区**纵向范围就等于浮动盒自身高度**，归零之后文字彻底不绕。对照实验：`height: 0` 压图 7 行、`85px` 压 3 行、`170px` 压 0 行。

**现在用的做法：把 widget 钉成一行。**

把 `.cm-embed-block` 的高度压到一行（约 26px），源码压缩不可见（只读），内部 SVG 用绝对定位溢出显示，后续行加 `padding-right` 留白。

关键是：**CM6 量到 26，记账 26，DOM 实际也占 26，三方一致，一分不差。** 而文字因为留白变窄、折行变多、行变高，这是**真实的 DOM 变化，CM6 会自己测量并更新账本**。

之前所有失败都是在骗账本，这个做法是让账本反映真实情况。

代价：代码块源码看不见、改不了，只能读。

**另外**：CM6 会把滚出视口的行整批销毁重建，`padding` 长在行元素上，行一换就丢。所以挂了个 `MutationObserver`（只看 `childList`，不观察 `style`，避免自己触发自己），攒一拍后整体重算。

**开关**：设置 → `Brace Map` → 「编辑模式浮动」，默认**关**。关着的时候编辑模式对布局零干预，光标和没装插件时一样。

**这个开关目前不推荐打开。** 打开后光标是正确的、图也能正常显示，但后续行的留白在真实 CM6 里反复失效，表现为文字压在图上、间歇性闪一下又散开。headless 里留白是成立的（文字右边界 464、图左边界 480、重叠 0 行），真机上不成立，原因至今未定位到。在查清之前，这个功能只在阅读视图里可靠。

**曾经尝试过、但无效的做法**（写下来免得重走）：

- 给后续行加 `padding-right`：headless 成立，真机不生效，且加上后又被抹掉
- `padding` 带 `!important`：不解决问题
- 同时给 `max-width` 兜底：不解决问题
- 「施加 → 下一帧复查 → 失败重写」三轮校验：不解决问题
- 1.2 秒巡检 + 插件加载完强制重算：只是让它间歇性地闪回来，反而增加复杂度，已回退

真机现象有一个很关键的细节：**刚打开 Obsidian 时文字是避开的，等所有插件加载完之后就不避开了**。这说明写入逻辑本身是对的，是之后某个时刻被破坏。但破坏者没有找到。

**已知上限**：图比它后面所有正文加起来还高时，留白只够盖到最后一行，多出来的部分会溢出。

### 为什么原生图片浮动就没这问题

Obsidian 把图片渲染成**行内**元素，塞在某一行文字流里。CM6 对它只有一个认知：「这一行就是正常行高」，**不单独给它记账**。主题（比如 Blue Topaz）给图片加 `float`，图片溢出到下面几行，文字绕开，CM6 的账一点没变——它没记错任何东西。

代码块是**块级 widget**，CM6 必须给它单独记一笔。记了就不能骗。

差别不在「图片特殊」，在于 **CM6 要不要为它单独记高度**。

## 架构

`src/` 是源文件，`main.js` 是产物。**`main.js` 由 `node build.js` 把 src 全部内联生成**，不读文件系统——因为 Obsidian 移动端（Capacitor）没有 `require`。

| 模块 | 职责 |
|---|---|
| `opt.js` | 布局参数常量（字号标定、括号形状比例、行距） |
| `util.js` | 极小的工具函数 |
| `text.js` | 行内语法解析（粗体/斜体/颜色/链接/公式切分） |
| `parse.js` | 代码块内容解析：指令区 + 缩进列表 → 树 |
| `measure.js` | 用 canvas 量文字宽度（不用 DOM，因为渲染时宿主可能不可见） |
| `wrap.js` | 按 `maxwidth` 折行，公式当作不可拆原子 |
| `layout.js` | 树 → 坐标：节点尺寸、列宽、行高、层级位置 |
| `brace.js` | 括号路径生成（curly / square，四种方向） |
| `svg.js` | 拼 SVG 文档 |
| `calibrate.js` | 渲染后二次校准：拿真实文本长度修正估算偏差 |
| `math.js` | MathJax 加载与公式转 SVG |
| `export.js` | 导出 SVG / PNG，底色解析 |
| `float.js` | 图文混排：阅读视图的 JS 模拟浮动 + 编辑模式的 CSS 浮动 |
| `remeasure.js` | 调 `cm.requestMeasure()` 的节流调度器 |
| `debug.js` | 运行时诊断日志（默认关闭） |

### 为什么用 canvas 量文字

Obsidian 渲染代码块时，宿主节点可能还没插进可见文档（`display: none` 或不在布局树里），这时用 DOM 量出来全是 0。canvas 的 `measureText` 不依赖布局，稳定。

但 canvas 有个坑：**离屏时 `getComputedStyle` 拿不到 font-size，`parseFloat('') || 14` 会兜成 14px**，导致折行宽度算错。解法是双级探针（先问宿主，拿不到问 `document.body`），并且 `ensureFont()` 独立于校准结果，无条件挂到可见节点上校验字号。

## 已知限制

1. **编辑模式的跨行环绕默认关闭**。开着会光标错位，这是 CM6 高度账本的结构性冲突，不是参数问题。详见上面「图文混排」。
2. **编辑模式下代码块源码不可见**（一行高度方案的代价），只读。
3. **图比后面所有正文还高时**，留白会不够，图会溢出到文档末尾之外。
4. **两张浮动图中间没有正文直接相邻**时，前一张脱离流后位置会塌，两张会叠在一起。阅读视图也一样。
5. **导出 PNG 里的公式**是矢量转位图，极高倍率下可能略有锯齿。
