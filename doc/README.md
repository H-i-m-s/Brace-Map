# Brace Map

把代码块里的缩进列表渲染成教材式的括号图（Brace Map），横向树、大括号连接，可导出 SVG / PNG。

Obsidian 插件，纯 JavaScript，无构建链、无 npm 依赖。

---

## 快速开始

在笔记里写一个 ` ```brace ` 代码块：

````
```brace
- 系统
  - 硬件
    - 传感器
    - 执行器
  - 软件
    - 固件
```
````

渲染出来就是：

```
                    ┌─ 传感器
          ┌─ 硬件 ─┤
          │         └─ 执行器
系统 ─────┤
          │         ┌─ 固件
          └─ 软件 ──┘
```

指令写在列表之前，一行一条，`键: 值` 的形式，可以混在列表中间写（解析器按行依次扫描，遇到列表项就进列表，遇到 `键: 值` 就当指令）。

## 节点文字换行

### 续行

一项的文字写不完时，下一行**缩进比上一个节点深**就并进同一个节点（续行），代码块里怎么换行，图上就怎么换行：

```
- 普通平键
  按端部形状分
  - A 型（双圆头）
```

渲染成两行「普通平键 / 按端部形状分」，下面再挂 A 型。

续行取 `trim` 之后的内容，行首的额外缩进不会带进文字。续行与 `<br>` 走同一条切分路径，效果一致，两者可以混着写；公式、链接、颜色在切分前已经变成原子，不会被换行拆断。续行里照常能写 `**粗体**`、`$公式$`、`[[双链]]`。

缩进**不深于**上一个节点的行不会被并进去（跟以前一样忽略）。续行里写 `float: left` 这种白名单内的指令仍然算指令；不在白名单里的（`注意: xxx`、`note: xxx`）按正文处理，不会被当成指令吞掉。

### `<br>` 硬换行

需要强制断行时，在文字里写 `<br>`（也认 `<br/>`、`<br />`，大小写无所谓）：

```
- 普通平键<br>按端部形状分
```

`<br>` 本身不显示，两侧不留空格；行首行尾写它不会产生空行。它和 `maxwidth` 叠加使用：先按 `<br>` 分段（续行留下的换行符同样算一段），每段内部再自动折行。行距沿用多行节点的那一档。公式是原子，`$...$` 里的 `<br>` 不会把公式切断。

### 空行

代码块里空一行，图上对应位置就空出一行的距离。一个空行是一整行（文字行高 `lineH`），连空两行就是两行：

```
- 受载方向分
  - 向心轴承
  - 推力轴承
  - 向心推力轴承

- 滚动体形状分
  - 球轴承
  - 滚子轴承
```

空行隔开的是「它所在那一层」，也就是按较浅的一侧算：上面这例里空行在 `向心推力轴承` 之后、`滚动体形状分` 之前，最近的共同层级是根，所以间距加在两个一级节点之间，不牵扯各自的子项。落在同一个父节点的两个子项之间时，加在那个父节点的子项间距上。

开头和结尾的空行、指令区（`dir:`、`float:` 等）之间的空行不产生间距。夹在同一个节点的续行之间的空行也不产生空行，续行照旧接进同一个节点。

## 指令

### `dir` — 展开方向

| 值 | 含义 |
|---|---|
| `lr` | 从左往右（默认） |
| `rl` | 从右往左 |
| `tb` | 从上往下 |
| `bt` | 从下往上 |

### `brace` — 括号形状

| 值 | 含义 |
|---|---|
| `curly` | 花括号 `{`（默认） |
| `square` | 方括号 `[` |

### `box` — 给指定层级画方框

值可以是单个数字、逗号分隔（`1,3`）、范围之外的组合，按**深度**生效（根节点深度为 1）。

```
box: 2
```

表示第 2 层的所有节点都带方框。清除写 `box: none`。

### 行尾 `{box}` — 只给单个节点画框

上面那个是按层，想精确点名某几个节点时，在行尾加 `{box}`：

```
- 系统
  - 硬件 {box}
  - 软件
```

只给「硬件」画框，不看层级。可以同时用 `box: N` 和行尾标记，两者取并集。

### `closing` — 末端总括号

在内容最外侧画一条总括号，把选定的节点收在一起。**选中的节点跨层时是一条长括号直接穿过去，中间的行不切断、不闭合。**

````brace
closing: true                    # 框住所有叶子节点
closing: 电动机, 内燃机, 齿轮      # 只框这三个
closing: 带传动，液压传动          # 中文逗号也行
closing: false                   # 显式关闭
````

**写名字的时候：**

- 按节点渲染出来的文字精确匹配，`trim` 后全等，大小写敏感，内部空格算数
- 同名节点全部框进去
- 名字一个都没匹配上 → 这一组跳过，不画也不报错
- 名字写错不要紧，但要自己意识到那条什么都没画

**给这一组起个名：**在末尾用 `=` 接一段标签，会写在该括号尖端的外侧、垂直居中。

````brace
closing: 动力组 = 电动机, 内燃机, 齿轮
closing: 全部 = true
````

分隔符取「第一个两边带空白的 `=`」。所以 `A=B = 甲` 的标签是 `A=B`，`组 = E=mc2` 的名字是 `E=mc2`；`组=甲` 这种一个空格都没有的写法退回第一个 `=`。标签不解析行内标记，`**粗体**` 会原样连星号一起画出来。

**多条并存：**先按书写顺序定列，**垂直方向不冲突的括号并排共用一列**，只有盖到已画括号的才往外推一列。列间距默认是 `braceWidth + colGap`；如果左边那列带标签，会再多让出「标签宽 + 一个 colGap」，否则标签会压在右边那列的括号上。

````brace
closing: 甲, 乙
closing: 丙, 丁
closing: true
````

上面这个只占两列：甲乙和丙丁上下不重叠，同列并排；总括把两段都盖住了，才占到外面一列。想只要分组不要总括，把第三行去掉就行。

**不写 `closing`** 就是一条都不画。

### `title` — 标题

图上方居中显示的标题。也兼容把 `# 标题` 写在第 1 行。

### `maxwidth` — 节点文字折行宽度

单位是最终 SVG 坐标里的像素，**不随字号缩放**。超过这个宽度的节点文字会自动折行。

```
maxwidth: 240
```

不写或写错值就是完全不折行。

### `float` — 图文混排

| 值 | 含义 |
|---|---|
| `l` / `left` | 靠左浮动，文字在右侧绕 |
| `r` / `right` | 靠右浮动，文字在左侧绕 |
| `c` / `center` | 居中，不浮动 |
| `inl` / `inline` | 行内模式 |

**注意**：`left` / `right` 的**跨行环绕只在阅读视图生效**，编辑模式下默认关闭。原因见下面「图文混排」一节。

### `width` — 浮动时的宽度

```
width: 300
```

不写就按图自身宽度。也支持 `300px`、`50%` 这类 CSS 宽度值。

### `bg` — PNG 导出底色

| 值 | 含义 |
|---|---|
| 不写 | 透明（默认） |
| `theme` | 取当前主题的背景色 |
| 任意颜色值 | 如 `#1a1a1a`、`rgb(20,20,20)` |

## 行内样式

节点的文字里可以用 Markdown 行内语法：

| 写法 | 效果 |
|---|---|
| `**粗体**` | 粗体 |
| `*斜体*` | 斜体 |
| `~~删除线~~` | 删除线 |
| `==高亮==` | 背景高亮 |
| `[[某篇笔记]]` | 双链，点击跳转 |
| `[文字](https://...)` | 外链，点击用系统浏览器打开 |

双链和外链在导出的 SVG 里会保留为 `<a>`，图片里则变成普通文字。

### 公式

支持 `$...$` 行内公式和 `$$...$$` 块级公式。公式被当作**不可拆的原子**参与排版，不会被 `maxwidth` 从中间折断。

渲染走插件内自带的 MathJax（`vendor/tex-svg.js`，2MB 左右），输出**矢量** SVG，导出时不会糊。

为什么不用 Obsidian 内置的：Obsidian 安装包里的 MathJax 只带 CHTML 输出，出不了矢量。这是实测结论（`tex2svg` 出现 0 次，`CHTML` 出现 307 次）。

## 图文混排

这部分是本插件踩坑最多的地方，写清楚留给以后。

### 阅读视图

散文区（`.markdown-preview-sizer`）是**纵向 flex 容器**，代码块是它的直接子项。CSS 规范明确：**flex 容器的直接子项，`float` 不产生浮动效果**（计算值还是 `right`，布局上被忽略）。

所以阅读视图的浮动是 **JS 模拟**的：

1. 容器 `position: absolute`，贴住正文列的左/右边界
2. 遍历它后面的兄弟块，按真实渲染高度累积，算到图的范围为止
3. 给这些块加 `margin-right` + `max-width`（两个都要，只加 margin 时定宽的块不会变窄）
4. 重算前先复位上一次的改动，不叠加

这条路是稳的，静态渲染没有虚拟滚动，不用担心坐标系。

### 编辑模式

编辑模式是 CodeMirror 6，情况完全不同，值得单独记。

**第一个坑：`.cm-content` 是 flex 子项，但它是 BFC。**

`.cm-embed-block` 直接挂在 `.cm-content` 下（Obsidian 1.13.7 实测，中间没有 `.cm-line`，老版本可能有）。因为 `.cm-content` 是 flex 容器的子项，**flex item 天然建立独立格式化上下文**，所以 `float` 在这里**有效**，文字会真的绕上来。

**第二个坑：`contain: paint !important` 会把图整张裁掉。**

Obsidian 的 `app.css` 里有这么一条（从 `obsidian.asar` 里确认过）：

```css
.markdown-source-view.mod-cm6 .cm-content > [contenteditable=false] {
  contain: paint !important;
}
```

代码块 widget 正是 `.cm-content` 下 `contenteditable=false` 的子元素。`contain: paint` 把后代裁到自己的 padding box，**`overflow: visible` 对它无效**——两套机制不是一回事。表现为：SVG 在 DOM 里、`getBoundingClientRect` 报正常尺寸，但视觉上完全看不见。

修法：不再逐层写行内样式，改为 `styles.css` 里一条静态规则

```css
.markdown-source-view.mod-cm6 .cm-content > .cm-embed-block:has(.brace-map-block) {
  overflow: visible !important;
  contain: none !important;
}
```

不依赖 JS 在不在，图刚重建、开关刚关掉的那一瞬也成立。`contain` 一旦留着，`.cm-embed-block` 就成了独立格式化上下文，浮动穿不出去，文字也不会绕——所以这条同时是「绕排」的前提。

**第三个坑（也是这个功能的全部）：CM6 的高度账本，其实不用骗。**

CM6 用**累加行高**估算文档总高和每行的位置，点鼠标时按这本账反推。block widget 会被单独记一条高度：如果 widget 浮动起来（实际占 0）、账上还是原高度，光标就会按错账落点（实测点第 18 行落到第 14 行，还能飘到行间空隙里）。

前几版都在想办法「把账做平」：widget 钉成一行 + 图绝对定位溢出 + 后续行 padding 留白；更早还有 `height: 0`、`shape-outside`、`requestMeasure` 主动重测。这些全是在**骗**账本，所以要么光标错位，要么文字不绕。

**决定性的一次实测**：把「编辑模式浮动」关掉之后，编辑模式反而图文混排正常、光标也正确。顺着查下去，答案是——根本不需要那么复杂：

1. 宿主（`.block-language-brace`）写 `float` 之后，`.cm-embed-block` 里只剩浮动子元素，**高度自然塌成 0**；CM6 量到 0、记 0，DOM 与账本两边一致，光标不会错位
2. `.cm-embed-block` 不是独立格式化上下文（下面那条 `contain` 被抹掉了），浮动因此**穿透到 `.cm-content`**
3. `.cm-content` 是 flex item，自成格式化上下文，后面的 `.cm-line` **真的绕排**

headless 复刻实测（图 300×170、正文列 800、8 行文字）：

| 条件 | embed 高度 | 前两行文字右边界 | 图左边界 | 压在图上 |
|---|---|---|---|---|
| `contain: paint` 还在 | 170 | 803 | 516 | 否（但也不绕，图占整行）|
| `contain` 抹掉、只写 float | **0** | **499** | 516 | **0 行** |

所以编辑模式的实现是：**一行 float + 一条 CSS 兜底**。没有高度干预、没有留白计算、没有观察者、没有定时器、没有时间线。

- 写：`applyFloatLayout(host, cfg)` → `float` + `width` + `margin`
- 兜底：`styles.css` 里 `.cm-embed-block:has(.brace-map-block) { overflow: visible !important; contain: none !important }`（静态规则，不依赖 JS 在不在）
- 开关：设置 → `Brace Map` → 「编辑模式浮动」，默认**开**。关掉时撤掉那行 float，图占整行。

**代价**：widget 高度是 0，所以代码块源码在编辑模式里不可见（只读）。要改源码就切到源码模式或者关掉开关。

### 为什么原生图片浮动就没这问题

Obsidian 把图片渲染成**行内**元素，塞在某一行文字流里。CM6 对它只有一个认知：「这一行就是正常行高」，**不单独给它记账**。主题（比如 Blue Topaz）给图片加 `float`，图片溢出到下面几行，文字绕开，CM6 的账一点没变——它没记错任何东西。

代码块是**块级 widget**，CM6 必须给它单独记一笔。记了就不能骗。

差别不在「图片特殊」，在于 **CM6 要不要为它单独记高度**。

## 架构

`src/` 是源文件，`main.js` 是产物。**`main.js` 由 `node build.js` 把 src 全部内联生成**，不读文件系统——因为 Obsidian 移动端（Capacitor）没有 `require`。

| 模块 | 职责 |
|---|---|
| `opt.js` | 布局参数常量（字号标定、括号形状比例、行距） |
| `util.js` | 极小的工具函数 |
| `text.js` | 行内语法解析（粗体/斜体/颜色/链接/公式切分、`<br>` 硬换行分段） |
| `parse.js` | 代码块内容解析：指令区 + 缩进列表（含续行）→ 树 |
| `measure.js` | 用 canvas 量文字宽度（不用 DOM，因为渲染时宿主可能不可见） |
| `wrap.js` | 按 `maxwidth` 折行，公式当作不可拆原子 |
| `layout.js` | 树 → 坐标：节点尺寸、列宽、行高、层级位置 |
| `brace.js` | 括号路径生成（curly / square，四种方向） |
| `svg.js` | 拼 SVG 文档 |
| `calibrate.js` | 渲染后二次校准：拿真实文本长度修正估算偏差 |
| `math.js` | MathJax 加载与公式转 SVG |
| `export.js` | 导出 SVG / PNG，底色解析 |
| `float.js` | 图文混排：编辑模式那一行 float + 阅读视图的 JS 模拟浮动 + 裁剪链体检 |
| `debug.js` | 运行时诊断日志（默认关闭） |

### 为什么用 canvas 量文字

Obsidian 渲染代码块时，宿主节点可能还没插进可见文档（`display: none` 或不在布局树里），这时用 DOM 量出来全是 0。canvas 的 `measureText` 不依赖布局，稳定。

但 canvas 有个坑：**离屏时 `getComputedStyle` 拿不到 font-size，`parseFloat('') || 14` 会兜成 14px**，导致折行宽度算错。解法是双级探针（先问宿主，拿不到问 `document.body`），并且 `ensureFont()` 独立于校准结果，无条件挂到可见节点上校验字号。

## 已知限制

1. **编辑模式下代码块源码不可见**（widget 身高 0 的代价），只读。要改源码切源码模式或关掉开关。
2. **图比后面所有正文还高时**，后面的正文会不绕一圈，图下方留白到底就正常排版了（图本身不会被裁）。
3. **两张浮动图中间没有正文直接相邻**时，前一张脱离流后位置会塌，两张会叠在一起。阅读视图也一样。
4. **导出 PNG 里的公式**是矢量转位图，极高倍率下可能略有锯齿。

## 有意不做

这些不是遗漏，是权衡之后的决定。每条写清楚为什么不做，以及真要做从哪下手。

### `box` 不支持范围写法

`box` 只认整数列表（`1,2` 或 `1 2`）。写 `1-3` 会被读成 `1`（`parseInt('1-3')` 返回 1），**不报错**。

**为什么不做：**这个指令用得不多，写全列表多不了几个字符；加范围解析要处理 `1-3`、`1,3-5`、`-2` 这些歧义，收益不抵复杂度。

**要做的话：**`src/parse.js` 的 `parseBox`，在按逗号/空格切分之后加一层区间展开。

### `closing` 点不到多行文字的节点

名字匹配的是节点渲染后的整段文字。含 `<br>` 或续行的节点，`text` 里有 `\n`，要整段全等才中。

**为什么不做：**放宽成「匹配第一行」会让 `甲<br>乙` 和 `甲<br>丙` 无法区分，那是更糟的隐式错误。

**要做的话：**要么加「取第一行」的显式语法，要么给节点加显式 id。

### 竖方向（`tb` / `bt`）的标签横写

`closing` 的标签在竖向图里仍然横排，占的是 cross 方向宽度。组名越长，画布越宽，整图看起来会右偏。

**为什么不做：**转 90° 能把这部分宽度换成沿 main 的进深，但要处理旋转后的文字基线、包围盒、导出兼容，改动面比收益大。

**要做的话：**`src/layout.js` 里标签定位那几行，加一条 `dir === 'tb' || dir === 'bt'` 的分支，用 `transform: rotate(-90)`。

### 标签不解析行内标记

`closing: 组名 = ...` 的组名走 `esc` 后原样输出，`**粗体**` 会连星号一起画出来，宽度也按星号算。

**为什么不做：**标签是「给括号起的名字」而不是正文，纯文本更可预测；解析它还要处理嵌套标记和宽度测量的一致性。

**要做的话：**`src/svg.js` 里 `bm-closing-label` 那个元素，换成和节点文字同一条渲染路径。

### 编辑模式和阅读视图是两套浮动实现

编辑模式用原生 `float` 让浏览器绕排；阅读视图里宿主是 flex 子项，`float` 不生效，只能绝对定位 + 逐段加外边距手动模拟。

**为什么不做：**统一成一套，要么牺牲编辑模式的「光标不错位」，要么牺牲阅读视图的「真绕排」，两边都有硬约束。

**要做的话：**没有干净的统一方案。真要到那一步，只能等 Obsidian 的预览层换布局模型。

### `valign` 在阅读视图的真机验证只做过一轮

逻辑上的坑都修了（未连入 DOM 被提前 dispose、高 0 的壳被当成块、量不到时撤销结果），headless 全绿，但真实 Obsidian 里只在一台机器、一篇笔记上验过。

**为什么停在这：**剩下的只能靠用出来。

**遇到不对的时候：**先跑「Brace Map: 显示 valign 对齐标记」，红线绿线差多少就是偏多少。
